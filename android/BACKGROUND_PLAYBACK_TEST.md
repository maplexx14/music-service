# Фоновое воспроизведение: исправление и проверка 10.11.2026

Исправлен воспроизведённый сценарий зависания потока посреди трека. Раньше
восстановление проверяло только `currentTime === 0`: если сервер переставал
отдавать байты после начала воспроизведения, позиция замирала, а плеер продолжал
показывать «играет» без повторного запроса.

В APK существующий watchdog теперь проверяет продвижение позиции и поступление
данных. После 12 секунд без продвижения и 8 секунд без новых данных он
перезагружает поток с сохранением позиции. Максимум три попытки с увеличенным
интервалом; новые попытки разрешаются после реального продвижения аудио.
При отсутствии сети повторная загрузка ждёт её возвращения. Ручная пауза,
системная пауза, смена трека и размонтирование отменяют ожидающее восстановление.
Поздний `canplay` проверяет актуальное намерение играть, а не старое замыкание.
Android-браузеры и iOS новый механизм не используют.

## Сравнение в настоящем WebView

Среда: Android 15 / API 35, AVD `bolt_api35` (Pixel 7), отладочная оболочка
**1.8 / versionCode 9** из `7c96ace`. В изолированную тестовую сборку добавлено
только доверие HTTPS-сертификату локального сервера для адреса `10.0.2.2`.
Оригинальные release APK и настройки доверия Android не изменялись.

Сервер отправлял первые 20 секунд восьмиминутного WAV, затем оставлял HTTP-ответ
открытым без новых байтов и EOF. Последующие запросы обслуживались с Range.
Контрольный Player взят из `7c96ace`; исправленный — из рабочего дерева.
Во время наблюдения CDP отключён, ADB-команды не выполнялись, экран заблокирован.

| Проверка | Старый Player | Исправленный Player |
| --- | --- | --- |
| Длительность наблюдения | 75,429 с | 380,273 с |
| Результат | Позиция застыла на 18,682 с | Продолжает играть, позиция 368,011 с |
| Восстановление после исчерпания буфера | Не произошло | Через 12,305 с, одна попытка |
| Позиция первого `playing` после восстановления | — | 18,689 с, совпадает с местом остановки |
| Новое соединение | Нет | `Range: bytes=622592-` |
| Отметки продвижения в фоне | 2 | 37 |
| Ошибки media element | Нет | Нет |

В конце исправленного прогона сервис оставался foreground, AudioFlinger показывал
активный AudioTrack. `playbackState=playing` сам по себе недостаточен для оценки:
в контрольном прогоне он оставался таким даже при зависшем аудио.

После восстановления системная кнопка Pause удерживала позицию **407,204 с**
неизменной в течение 30,192 с (`requested=false`, `paused=true`). Только после
системной команды Play позиция снова выросла до **409,253 с**. Журнал crash пуст.

## Область результата и выпуск

Восстановление совместимо с уже установленной оболочкой 1.8: пользователям
достаточно получить обновлённый фронтенд при загрузке приложения. Исправление
опубликовано на boltmusic.lat 10.11.2026 в коммите `69b3fd9`.
[CI](https://github.com/maplexx14/music-service/actions/runs/42845273937) и
[CD](https://github.com/maplexx14/music-service/actions/runs/42846228430) завершились
успешно. Публичный сайт отдаёт `/assets/index-BIqALuv6.js` с новой логикой
восстановления; HTML имеет `Cache-Control: no-store`, `/api/health` — `healthy`.
Проверка выполнена в 15:38 UTC; результат сохранён в
`app/build/reports/deployment/production-check.json`.
Для загрузки обновления установленное приложение нужно полностью закрыть
и открыть заново при доступной сети; опубликованная версия APK остаётся 1.8.
Нативная настройка исключения из оптимизации батареи относится к отдельной
оболочке 1.9 и требует сборки с прежним release-ключом.

Этот тест подтверждает конкретный сетевой сбой и его исправление. Он не доказывает,
что именно этот сбой вызвал исходное сообщение с Samsung S25. Ограничения One UI
и жизненный цикл авторизованного Layout не воспроизводились. Звук проверялся по
прогрессу и Android AudioTrack, акустическая проверка не выполнялась (`-no-audio`).
Системная пауза проверена регрессионными тестами; попытка эмулировать звонок не
создала активного вызова, поэтому проверкой настоящего звонка не считается.
