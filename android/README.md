# bolt для Android

Нативная оболочка (Kotlin, WebView) над мобильной версией https://boltmusic.lat:
интерфейс и функции — те же, что у сайта, обновляются вместе с деплоем фронта.
Сверху нативное: фоновое воспроизведение (foreground service + wake lock),
системный плеер в шторке/на экране блокировки/гарнитуре из `navigator.mediaSession`,
«Поделиться» через системный лист, выбор файлов, «Назад» сворачивает приложение
на корне вместо закрытия. Мост — `app/src/main/assets/bridge.js`.

Системный «Назад» сначала вызывает `window.__boltHandleBack`: страница
закрывает диалог, полноэкранный плеер или караоке, затем возвращается по
маршрутам. Только главная без открытых окон позволяет свернуть приложение.
Оболочка сообщает поддержку через `__boltNativeBack`; старые APK продолжают
использовать историю браузера. Кнопки уведомления отправляют отдельные
команды предыдущего/следующего трека прямо в `PlaybackService`; экран
блокировки и гарнитура используют callbacks `MediaSession`.

Уведомление имеет собственные компактную (48 dp) и развёрнутую компоновки
на всю доступную ему ширину. Слева — предыдущая композиция, справа — следующая;
команды перемотки не объявляются как кнопки сессии, перемотка остаётся через
`seekto`. Прошивки могут сами выделять медиаплееру отдельную область шторки:
её размер приложение изменить не может.

Для системных музыкальных панелей, включая острова/капсулы прошивок,
используется стандартная активная `MediaSession` с локальным аудиопотоком
`STREAM_MUSIC`, `MediaStyle`, названием, исполнителем, обложкой, длительностью
и состоянием воспроизведения. Публикация в магазине vivo для этого не нужна.
Показывать ли эту сессию в острове, решает прошивка; требуется проверка на
конкретном устройстве. Отдельный API «атомных уведомлений» vivo здесь не используется.

## Сборка

Нужны JDK 17 и Android SDK (platform 35). На маке разработчика они лежат в `~/android-dev`:

    export JAVA_HOME=~/android-dev/jdk-17.0.20.1+1/Contents/Home
    export ANDROID_HOME=~/android-dev/sdk
    ./gradlew assembleRelease

APK: `app/build/outputs/apk/release/app-release.apk`.

Подпись берётся из `keystore.properties` (не в git; ключ `~/android-dev/bolt-release.jks`).
Обновления ставятся поверх только с тем же ключом — не терять. Для каждой новой
версии поднять `versionCode` в `app/build.gradle.kts`.
Без `keystore.properties` release-сборка остаётся неподписанной
(`app-release-unsigned.apk`); публиковать её вместо `frontend/public/bolt.apk` нельзя.

Debug-сборка включает удалённую отладку WebView (`chrome://inspect`).

На Windows с настроенными JDK 17 и Android SDK: `.\gradlew.bat assembleRelease`
(из папки `android`).

Проверка веб-обработчика и моста без устройства: `npm run test:android` из `frontend`.
Проверка нативных кнопок, сессии и обеих компоновок на Android 15:
`.\gradlew.bat testDebugUnitTest lintDebug assembleDebug` из `android`.

После сборки проверить на vivo: открыть обычный плеер и караоке, вернуться
системным жестом; повторить с диалогом поверх плеера. В шторке и на экране
блокировки проверить переходы «предыдущий → следующий» на очереди из трёх
треков, затем повторить на другом Android-устройстве.

Версия исходников — 1.6 (`versionCode = 7`). Готовый `frontend/public/bolt.apk`
и `bolt-version.json` обновлять вместе только после сборки с прежним ключом
и проверки на устройстве.

Сайт читает `bolt-version.json` без HTTP-кэша. Android-браузеры и PWA показывают
уведомление о доступной версии; закрытие запоминается для этой версии.
В APK проверку и установку обновления выполняет `Updater` при запуске.
В браузере постоянная ссылка на скачивание есть на странице входа и в
«Настройки → Приложение → bolt для Android». Публикуемая версия — 1.6
(`versionCode = 7`), APK подписан прежним release-ключом.
