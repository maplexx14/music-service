Каталог для файла активного прокси (active.url), который пишет
proxy-pool/rotate.sh и читает бэкенд (STREAM_PROXY_FILE в docker-compose).

Смонтирован в контейнер бэкенда read-only как каталог, а не файл: rotate.sh
подменяет active.url через mv, то есть меняет inode, и bind-mount самого файла
продолжал бы показывать старую версию.

Пустой каталог — нормальное состояние: значит прокси не используется и аудио
качается напрямую. Сам active.url в .gitignore — в нём креды прокси.

Второй файл того же вида — soundcloud.url (SOUNDCLOUD_PROXY_FILE): выход для
МЕТАДАННЫХ SoundCloud, то есть api-v2 и скрейпа client_id. СЕЙЧАС ВЫКЛЮЧЕН —
обе переменные закомментированы в docker-compose.yml и docker-compose.prod.yml,
так что файл не читается даже если он есть. Чтобы включить: раскомментировать
SOUNDCLOUD_PROXY_FILE и прописать выход через pick-soundcloud-proxy.sh.

Он отдельный от active.url намеренно. Провайдер режет SoundCloud целиком:
soundcloud.com не открывается (ConnectTimeout), а api-v2 отдаёт 403 даже с
валидным client_id, и без прокси поиск по SoundCloud возвращает пусто,
потратив ~15 секунд. Но включать из-за этого active.url нельзя: он погнал бы
через платный выход ВСЁ googlevideo-аудио. Само аудио SoundCloud к IP выхода не
привязано (проверено byte-range запросом) и качается напрямую, так что платного
трафика здесь было бы только JSON метаданных.

Формат тот же: одна строка http://user:pass@host:port, строки с # игнорируются.
Бэкенд перечитывает файл по mtime, перезапуск контейнера не нужен.
