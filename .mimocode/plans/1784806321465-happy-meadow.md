# Оптимизация загрузок/скачиваний для слабого интернета

## Контекст

Текущее состояние:
- **Загрузка**: один монолитный FormData → POST /api/tracks/upload. Нет resume, при обрыве — начинай сначала. API timeout: 15с.
- **Стриминг**: <audio> с Range requests (HTTP 206). AAC-транскодирование ~30-50% экономии.
- **Инфра**: nginx client_max_body_size 1024m, gzip/brotli, proxy_buffering off.

## План

### 1. Backend: Chunked upload API (tracks.py)

Добавить 4 эндпоинта:

- POST /api/tracks/upload/init → { upload_id, chunk_size, total_chunks }
- POST /api/tracks/upload/chunk → { chunk_index, received }
- GET /api/tracks/upload/status/{upload_id} → { received_chunks[], total_chunks }
- POST /api/tracks/upload/complete → TrackResponse

Временные чанки в music_files/_uploads/<upload_id>/, после complete — склейка + mutagen + AAC + MinIO.

### 2. Frontend: chunkedUpload.js (новый)

Класс ChunkedUpload: File.slice(), sequential upload, retry 3x с экспоненциальной задержкой, resume через localStorage, AbortController, таймаут 30с/чанк.

### 3. UploadTrack.jsx: интеграция

Файлы > 2MB → ChunkedUpload, ≤ 2MB → существующий FormData. UI: прогресс по чанкам, "Продолжить загрузку?" при resume.

### 4. api.js: timeout 15с → 60с

### 5. Оптимизация сжатия

Уже есть: AAC + gzip/brotli + faststart. Дополнительно: brotli для proxied стриминга.

## Проверка

1. Загрузить файл > 2MB — чанки + прогресс
2. Убить соединение → восстановить → resume
3. POST /upload работает для малых файлов
4. Стриминг работает как раньше
5. AAC транскодирование работает
